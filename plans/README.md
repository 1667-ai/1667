## Findings considered and rejected

- Temporal fact states: shipped, user-tested, and removed; static facts cover the need, and “As of chapter 3: level 5” is authorable by hand.
- SQLite: rejected for this stage because the product explicitly promises local,
  inspectable files and no database; the current scale does not justify abandoning it.
- One compressed JSON file per story: reduces bytes but keeps whole-file rewrites,
  duplicated version text, and duplicated branch prefixes.
- Delta chains between versions: rejected because random access, corruption recovery,
  and history pruning become dependent on chain integrity.
- Fixed-size chunks: rejected because inserting text shifts every later boundary and
  destroys deduplication for the exact massive-part editing case being solved.
- One global object pool: rejected for v2 because stories cease to be self-contained
  and safe deletion requires global garbage collection/reference bookkeeping.
- Revision IDs in summary cache keys: rejected in review — any edit or append to a
  part (including empty-prompt Continue appending into the last part) changes the
  revision and would invalidate untouched leaves. Keys are content-based (chunk IDs +
  offsets) instead.
- Author-brief hash in summary cache keys: rejected in review — the brief is not a
  summarizer input, so keying on it only invalidated the whole cache on brief edits.
- Recursive rollup hierarchy (fan-out 8): trimmed to two tiers with bounded rollup
  output; a third tier requires a re-scope, not a unilateral addition.
- `contextMode` setting: cut — verbatim-when-fits plus compaction only under a known,
  overflowing window needs no new setting; clearing the context window is the escape
  hatch.
- Pinned fact rail + scroll-position tracking, review provenance (`needsReview`),
  temporal export annotations, 6 extra fact templates: deferred from Plan 003 with
  explicit triggers (see its "Deferred with triggers" section).
- A full character-card runtime, CharacterHub URL sync, avatars, greetings, card prompt
  overrides, and embedded lorebooks: rejected for Plan 006. The requested value is a
  reviewed one-time conversion of character-defining prose into existing flat facts.
- V3/CHARX/WebP card parsing: deferred until the source service makes one a default or
  a real user card demonstrates the need; V1/V2 PNG and JSON are the controlled slice.
- Context compaction inside Plan 001: deferred deliberately at the time; now Plan 002.
- Active-line semantics for the legacy standalone `POST /branch` endpoint (Plan 004
  review): rejected — the UI no longer calls it, promote covers the need, and tail
  part ids 404 honestly; extending legacy semantics is speculative work.
- Two-phase commit for summary-branch cancellation (Plan 004 review): rejected —
  an abort landing during the save is unwinnable without 2PC machinery; the client
  reloads after every cancel so a race-won branch is visible and one delete away.
- Autoname 409 when the active branch changes mid-naming (Plan 004 review):
  rejected — the title names the work, not a line; whichever line was visible when
  the user asked is a legitimate source.
